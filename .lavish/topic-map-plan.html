2 · Живой прототип

Как это будет ощущаться

Не мокап: те же 236 точек, предлагаемый рендер (SVG + CSS-transition по transform) и предлагаемые раскладки. Переключайте режим и год — цифры внизу считаются по-настоящему, на вашей машине.

раскладка посчитана за — видно точек — fps во время перелёта — перелётов 0
Снимите первую галочку и переключите год — это и есть разница между 60 fps и просадкой: блюр-фильтр перерастеризуется каждый кадр.
3 · Раскладки

Три раскладки одной и той же точки

Темы · все годы

Ровно то, что лежит в map.json: x,y ∈ [0,1] от supervised UMAP. Ничего не считаем.

px = x·100, py = y·64

Темы · один год

Не пересчитываем UMAP. Берём подмножество года, считаем его bbox и делаем аффинный зум с общим масштабом по обеим осям. Геометрия и соседства сохраняются — глаз читает это как «приблизили кусок карты», а не как «точки разбежались случайно».

s = min(0.86/w, 0.86/h, 2.2)
x' = 0.5 + (x−cx)·s

Таймлайн

Ось времени по дате поста (не по индексу), тема — дорожка. Внутри дорожки — beeswarm-раздвижка, чтобы всплески не слипались в одну кляксу.

t = (date−min)/(max−min)
lane = cluster → y

Мобильная ориентация — транспонированная

8 горизонтальных дорожек на 390-px экране дают 4-пиксельные полосы. Поэтому на <640 px таймлайн разворачивается: время идёт вниз (совпадает с направлением скролла), темы становятся колонками, viewBox вытягивается до 100×170. Это переключение — тоже просто другой аргумент orientation в той же чистой функции, отдельного кода рендера нет.

Попробуйте кнопку «Мобильный» в прототипе выше.

Ширина 330 px: пилюли годов скроллятся горизонтально, легенда возвращается на мобилу как скроллируемый ряд.

Почему выигрывает самый скучный вариант

На 250 точках узкое место — не количество точек, а feGaussianBlur: фильтр перерастеризует всю область при каждом кадре движения. Убираем анимацию у слоя свечения (гасим на 300 мс) — и SVG перестаёт отличаться от канваса по плавности, но сохраняет ховер, подписи, фокус с клавиатуры и серверный рендер. Канвас имеет смысл только если постов станет ~2000+; тогда его можно ввести за той же чистой функцией раскладки, не трогая всё остальное.

5 · Архитектура

Где считать раскладку

Главный вопрос — не «сервер или клиент», а «дорого или дёшево». Дорогое (эмбеддинги, UMAP) уже посчитано офлайн и лежит в git. Всё новое — O(n) арифметика по 236 точкам.

Производные раскладки
Зум года и таймлайн: сортировка + один проход раздвижки. Замерено в прототипе выше — смотрите «раскладка посчитана за».

Почему не Web Worker

Стоимость раскладки — доли миллисекунды на 236 точках (цифра в прототипе — настоящая). Воркер добавил бы асинхронность, сериализацию и отдельный бандл ради работы, которая дешевле одного кадра. Порог, после которого разговор про воркер осмыслен, — примерно 5000 точек или настоящий force-directed с итерациями.

Почему не пре-рендер кадров в map.json

Вариант «посчитать UMAP отдельно для каждого года и положить кадры в JSON» звучит быстрее, но даёт несопоставимые координаты: точка при фильтрации улетала бы в случайное место, анимация читалась бы как шум. Плюс это требует ключа OpenAI и перезапуска пайплайна. Аффинный зум на клиенте и дешевле, и честнее визуально.

Форма API

Одна функция, три режима, полностью тестируемая без DOM:

// lib/mapLayout.ts
export type LayoutOpts = {
  mode: 'topics' | 'timeline';
  year: string | null;          // '2024' | null = все
  orientation: 'h' | 'v';       // из media query на клиенте
};
export type Placed = { x: number; y: number; visible: boolean };

export function computeLayout(
  points: MapPoint[],           // { id, x, y, c, t }  t = timestamp
  opts: LayoutOpts,
): Map<number, Placed>          // O(n log n), 236 точек ≈ доли мс

Компонент никогда не хранит координаты в стейте — только {mode, year, cluster}. Всё остальное выводится. Скрытые точки не размонтируются: visible:false → opacity 0, поэтому React-дерево стабильно и переключение года не платит за монтирование.

6 · Порядок работ

Пять шагов, каждый — рабочее состояние

1

Рефакторинг без визуальных изменений

Вынести lib/mapLayout.ts, перевести точки на transform вместо cx/cy, увести ховер из React-стейта (CSS :hover + pointer-events на невидимых хит-кругах r≈3). Результат: карта выглядит идентично, но 472 узла больше не перерисовываются на каждое движение мыши, а тап на телефоне попадает. TopicMap.tsx, lib/mapLayout.ts

2

Данные и контролы

В page.tsx добавить к точкам t (timestamp из posts.json). Ряд пилюль годов + сегмент «Темы / Таймлайн», оба скроллируемые и видимые на мобиле; вернуть легенду тем на <640 px как горизонтальный скролл-ряд. page.tsx, TopicMap.tsx, globals.css

3

Фильтр по годам + анимация

Аффинный зум подмножества, стаггер по индексу (кап ~120 мс, иначе распад на «волну»), гашение слоя свечения на время перелёта, prefers-reduced-motion → мгновенно. Подписи кластеров едут к новым центроидам; при <3 точках в теме подпись скрывается. mapLayout.ts, globals.css

4

Режим таймлайна

Дорожки по темам, beeswarm внутри дорожки, ось лет, транспонирование на узком экране. Фильтр темы и фильтр года продолжают работать поверх режима — это ортогональные оси состояния. mapLayout.ts, TopicMap.tsx

5

Проверка

npx tsc --noEmit, npm run build, dev на :3199 + Chrome на ~430 px, профиль Performance с 4× CPU-throttle на переключении года (цель — отсутствие красных кадров), проверка отсутствия горизонтального оверфлоу (см. гоча про тултипы в CLAUDE.md).

7 · Риски

Что может пойти не так

iOS Safari и CSS-transform на SVG

Поддержка есть, но в связке с filter Safari иногда рисует блюр на CPU. Митигация: свечение и так гасится на время перелёта; если и этого мало — заменить feGaussianBlur на один статичный radial-gradient-фон, который просто кросс-фейдится.

2026 год — 34 поста на 8 тем

В разреженном годе подписи кластеров налезают друг на друга, а зум может раздуть 3 точки на пол-экрана. Митигация: кап масштаба s ≤ 2.2 и скрытие подписи темы, если в ней меньше 3 точек в текущем срезе.

Комбинация фильтров = пустой экран

«2022 + тема ИИ-инструменты» может дать ноль постов. Митигация: явное состояние «в этом году такой темы ещё не было» вместо молча пустого прямоугольника.

Три оси состояния в одном компоненте

TopicMap.tsx уже держит кластер, ховер и модалку; добавляются режим, год и ориентация. Митигация: один useReducer и вся геометрия — производная, ничего не дублируется в стейте.
